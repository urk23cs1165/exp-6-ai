Experiment 6: Conversational AI Agent with Medical Context Guardrails

1. Overview & Objective

Building upon the structural analysis completed in Experiment 5, this laboratory experiment guides students to transition a static informational pipeline into an interactive, multi-turn Conversational Medical AI Agent. The core focus is establishing real-world safety barriers, context preservation across messaging turns, and programmatic fallback rules to manage high-risk parameters.

Mandatory Safety Footnote:

This application framework is designed strictly for educational and classroom demonstration purposes. For medical guidance, treatment selection, or clinical diagnosis, always consult an accredited healthcare professional. Large Language Model evaluations are subject to hallucination and must include strict operational fallback boundaries.

2. System Architecture & Workflow

Students must build an asymmetric session handler that pipes live natural language chat through system rule validation before compiling the payload back to GPT-4. The structured runtime path maps down as follows:

Active Multi-Turn User Ingestion (Session State Handling)
▼
Guardrail Processing Node (Token/Intent Monitoring)
▼
System Role Custom Prompts with Verification Policies
▼
GPT-4 Inference Execution
▼

▼

▼
Mandatory Structural Disclaimer Injection

3. Implementation Guidelines & Code Components

A. Session Handling & Context Processing

To avoid context loss between individual inputs, code templates must preserve history matrices natively. Below is an example structured code schema:

import openai

class MedicalGuardrailAgent:
    def __init__(self, api_key):
        self.client = openai.OpenAI(api_key=api_key)
        self.session_history = [
            {"role": "system", "content": (
                "You are an educational medical assistant framework. Your role is general context parsing.\n"
                "CRITICAL POLICIES:\n"
                "1. If symptoms are inferred, provide exactly three (3) distinct medical possibilities.\n"
                "2. If general interventions are sought, detail exactly three (3) non-prescriptive options.\n"
                "3. Never provide infant therapeutic dosages or execute direct biometric math calculations.\n"
                "4. Always append a clear request advising users to double-check their physical packaging labels."
            )}
        ]

    def process_turn(self, user_message):
        # Append interactive text turn
        self.session_history.append({"role": "user", "content": user_message})
        
        # Execute GPT-4 Inference with integrated policy restrictions
        response = self.client.chat.completions.create(
            model="gpt-4",
            messages=self.session_history,
            temperature=0.2
        )
        
        assistant_reply = response.choices[0].message.content
        self.session_history.append({"role": "assistant", "content": assistant_reply})
        return assistant_reply

4. Mandatory Evaluation Matrix

Students will be graded based on how securely their system executes boundary isolation queries. Ensure the interface layout properly outputs structural information into the following defined schemas:

Safety Parameter Enforcement Standard Failure Condition Trigger
Differential Output Must display a minimum of 3 potential conditions using hedging syntax. Presenting a single absolute diagnosis.
Remediation Options Must outline exactly 3 general or self-care tracking strategies. Prescribing custom clinical medication parameters.
Label Check Policy Explicit message instructing physical confirmation of product labels. Omitting label checking alerts on clinical inquiries.
Infant/Biometric Restraints Immediate programmatic refusal to process dosage math metrics for infants. Calculating milligrams per body weight dynamically.

5. Exercise Assignments for Students

  1. Multi-turn Threading Tracker: Implement an in-memory or state-based session log tracking at least 5 message turns without dropping context attributes.
  2. Redundancy/Refusal Interceptor: Build a preprocessing regex or keyword handler to automatically throw an alternative safe warning prompt if extreme high-risk terms (e.g., severe anaphylaxis, continuous unresponsiveness) are caught.
